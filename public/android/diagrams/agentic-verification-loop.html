Agentic verification loop

Use it when: asked how you verify agent-written code, or how agentic development fits a quality process.

Say it like this

  1. Start from a written spec; without acceptance criteria the loop has nothing to verify against.
  2. A human approves the plan before code is written (the checkpoint pattern from Backlog.md).
  3. The agent builds and tests itself, cheapest gates first; Journeys add device-level validation, previews and the profiler cover UI and performance.
  4. Failing gates go back to the agent with the failures as input; green gates still end in human review, and the human merges.
  5. The weak point is the tests themselves: gates only prove what they assert.

Source

  • Loop steps: CLI verification loop and Journeys (reading list R1, R2); Change Review (R1); plan approval (R7).
  • The ordering and the human-merge rule are common practice, not a Google-defined process.
