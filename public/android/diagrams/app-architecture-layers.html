App architecture layers

Use it when: asked to structure an app or explain unidirectional data flow.

flowchart TD
  subgraph UIL["UI layer"]
    UI["Compose UI"]
    VM["ViewModel: state holder"]
  end
  subgraph DOML["Domain layer, optional"]
    UC["Use cases"]
  end
  subgraph DATAL["Data layer"]
    REPO["Repositories: single source of truth"]
    DS1["Network data source"]
    DS2["Database data source"]
  end
  UI -->|"events"| VM
  VM -->|"calls"| UC
  VM -.->|"calls, when there is no domain layer"| REPO
  UC -->|"calls"| REPO
  REPO --> DS1
  REPO --> DS2
  DS1 -.->|"data"| REPO
  DS2 -.->|"data"| REPO
  REPO -.->|"Flow of data"| UC
  UC -.->|"Flow of data"| VM
  VM -.->|"UI state"| UI

  classDef ui fill:#c7d2fe,stroke:#4338ca,color:#1c1917
  classDef logic fill:#bbf7d0,stroke:#15803d,color:#1c1917
  classDef data fill:#bae6fd,stroke:#0369a1,color:#1c1917
  class UI,VM ui
  class UC logic
  class REPO,DS1,DS2 data

Say it like this

  1. Solid arrows are events or calls going down; dotted arrows are data and state coming up. That is unidirectional data flow.
  2. Each kind of data has one owner, the repository, which is the single source of truth.
  3. The domain layer exists only for reused or complex logic; skip it otherwise (the dashed shortcut).
  4. Each data source handles exactly one origin: file, network or database.
  5. The ViewModel lives as long as the screen it serves and exposes immutable state.
