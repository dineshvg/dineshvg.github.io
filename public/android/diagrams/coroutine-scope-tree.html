Coroutine scope tree and cancellation

Use it when: asked about structured concurrency, who cancels what, or where to launch long-lived work.

flowchart TD
  VMS["viewModelScope<br/>cancelled when the ViewModel is cleared"]
  APP["Injected application scope<br/>outlives the screen"]
  VMS --> L1["launch: load screen"]
  VMS --> L2["launch: refresh"]
  L1 --> CS["coroutineScope"]
  CS --> A["async: load user"]
  CS --> B["async: load prescriptions"]
  APP --> SYNC["launch: upload pending changes"]

  classDef scope fill:#c7d2fe,stroke:#4338ca,color:#1c1917
  classDef work fill:#bbf7d0,stroke:#15803d,color:#1c1917
  classDef long fill:#fde68a,stroke:#b45309,color:#1c1917
  class VMS,CS scope
  class APP long
  class L1,L2,A,B,SYNC work

Say it like this

  1. Children belong to their parent: cancel the parent and every child is cancelled (structured concurrency).
  2. In a coroutineScope, if load user fails, load prescriptions is cancelled and the error propagates. In a supervisorScope, siblings keep running.
  3. Work that must outlive the screen, like uploading pending changes, goes in an injected application-level scope, never GlobalScope.
  4. Cancellation is cooperative: long loops call ensureActive(); never swallow CancellationException.
